# Техническое задание: модульное веб-приложение для раскладов Таро («Таро-оболочка»)

**Версия:** 1.3 (обновлено: 3 языка RU/EN/ES с первого дня, WhatsApp как будущий канал)
**Дата:** 2026-10-14
**Заказчик:** Владимир
**Язык интерфейса:** русский

> **Как читать этот документ.** ТЗ написано так, чтобы его мог выполнить и человек-разработчик, и ИИ-агент. Все термины объяснены в разделе 2. Пути вида `decks/<deck-id>/` — это папки в репозитории проекта. «MVP» — первая рабочая версия, «v1.1» — следующие шаги.

---

## 1. Цель и концепция

Создать модульную веб-«оболочку» (платформу), в которую блоками подключаются:

1. **Колоды карт** — на старте авторская колода «Космический мистицизм»: **полные 78 карт** (22 старших аркана — изображения 1280×1920 готовы; 56 младших арканов — отрисовка в том же стиле и размере);
2. **Расклады** — наборы позиций с толкованиями (карта дня, 3 карты, кельтский крест и др.);
3. Позже — **другие эзотерические системы** (Ленорман, руны, оракулы, И-Цзин) тем же механизмом плагинов, без переписывания ядра.

**Бизнес-модель (решение заказчика):** оба направления — **freemium** (что-то бесплатно, что-то платно).
- **Сайт (направление B):** бесплатно — регистрация, каталог карт, базовые расклады с краткими толкованиями («осмотреться»); платно — ИИ-толкования DeepSeek, продвинутые расклады, расширенные лимиты. Точная граница free/paid — решением заказчика (открытый вопрос).
- **«Таролог» (направление A):** бесплатно — карта дня; платно (подписка) — расклады и ИИ-толкования в боте.
- Подписка закладывается в архитектуру v1 (таблица подписок, проверка доступа, paywall-заглушки); подключение реального платёжного провайдера — этапом после MVP по решению заказчика.

**Принципиальные ограничения (от заказчика):**
- Авторизация и привязка бота — **строго по образцу приложения Help** (логин/пароль, cookie-сессии, одноразовый код привязки). Паттерн разобран и задокументирован отдельно (`research-help-pattern.md`). Никаких альтернативных способов входа в v1.
- **Инфраструктура — как в Help:** сервер на Cloudflare Workers (у заказчика уже есть), база данных — **Neon Postgres, бесплатный тариф** (на старт хватит). Стек повторяет Help: Node.js + Express, бот на Telegraf/grammY, Prisma ORM.
- **Толкования карт — через DeepSeek** (как ИИ-репетитор в Help/English работает через прокси): приложение отправляет расклад в DeepSeek с заранее составленным системным промптом и показывает сгенерированное толкование. Статические тексты в JSON — только как запасной вариант при недоступности API.
- **Три языка с первого дня:** русский, английский, испанский. Язык выбирается при регистрации (есть переключатель), весь интерфейс, толкования и бот работают на выбранном языке. Одновременного показа на трёх языках нет — только переключение.

## 2. Термины

- **Колода** — набор карт: папка с изображениями + `cards.json` с толкованиями.
- **Расклад (спред)** — JSON-описание: число позиций, схема расположения карт на «столе», смысл каждой позиции.
- **Позиция** — слот в раскладе: координаты (x, y), поворот, текстовый смысл («Прошлое», «Препятствие»…).
- **Вытягивание** — случайный выбор N карт из колоды (с учётом перевёрнутых, если включены).
- **Карта дня** — ежедневный автоматический расклад из 1 карты с пушем в Telegram.

## 3. Функциональные требования

### 3.1. Каталог колод и раскладов
- F-01. Пользователь видит список доступных колод (v1: одна — «Космический мистицизм», 78 карт).
- F-02. Пользователь видит список раскладов с кратким описанием и числом карт.
- F-03. Новая колода добавляется **без изменения кода**: папка `decks/<deck-id>/` с изображениями + `cards.json`.
- F-04. Новый расклад добавляется **без изменения кода**: файл `spreads/<spread-id>.json` (+ опциональный JS-модуль кастомного рендера) + запись в `spreads/registry.json` (вкл/выкл, порядок в каталоге, видимость в боте). Каждый расклад независим: подготовил → включил флаг → он работает, остальные не затрагиваются.
- F-04a. **Энциклопедия значений** (паттерн всех конкурентов): публичный раздел со значениями всех 78 карт — картинка, прямое/перевёрнутое толкование, ключевые слова, на 3 языках. Даёт сразу три вещи: SEO-трафик («значение карты ...»), доверие («у них есть база знаний») и готовый контекст для ИИ-промпта. Генерируется из тех же `cards.json`, отдельная работа не нужна.

### 3.2. Расклады v1 (MVP)

| Расклад | Карт | Позиции |
|---|---|---|
| Карта дня | 1 | Тема дня |
| Да / Нет | 1 | Прямая = «да», перевёрнутая = «нет» (метод фиксируется, см. ниже) |
| Три карты | 3 | Прошлое / Настоящее / Будущее |
| Малый крест | 5 | Ситуация / Препятствие / Корень / Уходящее / Направление |
| Кельтский крест | 10 | 10 классических позиций (см. Приложение A); карта 2 — горизонтально поверх карты 1, карты 7–10 — вертикальный «посох» справа |

Метод «Да/Нет» фиксированный: прямая карта — «да», перевёрнутая — «нет»; дополнительно показывается краткое толкование карты. Настройка «использовать перевёрнутые карты» (вкл/выкл) — глобальная для пользователя, по умолчанию **вкл**. Все расклады используют полную колоду 78 карт.

### 3.3. Движок расклада
- F-05. Перетасовка колоды (криптографически стойкий RNG, `crypto`/`secrets`).
- F-06. Анимация вытягивания: рубашка → переворот карты (CSS-анимация, без тяжёлых библиотек).
- F-07. Под каждой картой: название, смысл позиции, толкование (прямое/перевёрнутое), ключевые слова.
- F-08. Кнопка «Новый расклад» (повторное вытягивание), кнопка «Сохранить в историю».
- F-09. История раскладов пользователя (дата, расклад, карты, толкования) — просмотр и удаление.
- F-10. «Избранное»: пометить расклад звёздочкой.

### 3.4. Два направления — одно ядро (решение заказчика)
- F-11. Внешне — **два независимых продукта** (допустимо позиционирование как конкурирующих, общий владелец не афишируется): **(A)** Telegram-бот «Таролог» — аналог ArcanaGuruBot; **(B)** сайт со своим Telegram-ботом «Уведомитель». Никаких ссылок друг на друга, кросс-промо нет. Внутренне — **одно ядро**: один бэкенд, одна БД, одна колода (78 карт), один движок раскладов, один ИИ-модуль толкований, один планировщик. Два бота — лишь два интерфейса поверх ядра (два токена BotFather, два webhook-эндпоинта). Ничего не дублируется: все расклады обоих направлений идут из одной базы. Нейминг и визуальная айдентика направлений — раздельные (решает заказчик).
- F-12. **Направление B — сайт + бот «Уведомитель» (бесплатно).** Уведомитель — спутник сайта, только для зарегистрированных на нём. Привязка — код из ЛК или deep-link `t.me/<bot1>?start=<payload>`. Единственная функция — уведомления: «Ваш расклад готов — смотрите в личном кабинете» + кнопка на сайт (deep link с автовходом, без повторного логина). Раскладов и ИИ внутри бота нет → нулевые переменные затраты. Цель — ежедневный возвратный трафик на сайт.
- F-13. **Направление A — бот «Таролог» (платно, прямой конкурент ArcanaGuruBot).** Полноценные расклады внутри Telegram: выбор расклада, вопрос пользователя, вытягивание карт (изображения нашей колоды 78 карт), ИИ-толкование через DeepSeek, карта дня пушем. Дифференциаторы: авторская колода, 3 языка с первого дня, общая история с сайтом.
- F-14. Привязка аккаунта (оба бота) — как в Help: `/start` → одноразовый код (TTL 10 минут) → ввод в ЛК; либо deep-link в один тап.
- F-15. **Карта дня и все функции «Таролога» — только при активной платной подписке** (см. 3.4.1). «Уведомитель» бесплатен всегда и подписки не требует.
- F-16. Планировщик (тик каждые 5–15 минут): «Уведомитель» — уведомления тем, у кого готов расклад / наступило время карты дня; «Таролог» — карта дня подписчикам по их локальному времени и часовому поясу.
- F-17. Защита от дублей: реестр `(user_id, bot_id, date)` с уникальным ключом.
- F-18. Формат сообщений: «Уведомитель» — короткий текст уведомления + кнопка «Смотреть» (на сайт). «Таролог» — фото карты (`sendPhoto`, подпись до 1024 символов: название + толкование). Ссылок на сайт у «Таролога» нет (направления раздельные).
- F-19. Честность: карта дня детерминирована — `seed = user_id + date`, «перевытянуть» нельзя.
- F-20. Отписка: команда `/stop` в боте и тумблер на сайте. 403 от Telegram (пользователь заблокировал бота) — пометка неактивности, джоб не падает.
- F-21. Команды. «Уведомитель»: `/start` (привязка), `/stop`, `/help`. «Таролог»: `/start`, `/link <код>`, `/unlink`, `/stop`, `/day` (карта дня по запросу), `/language`, `/help`.

### 3.4.1. Подписка (paywall)
- F-18a. Сущность `subscriptions`: user_id, plan (monthly/yearly), started_at, expires_at, status (active/expired/cancelled), payment_provider, external_id.
- F-18b. Проверка доступа: любой запрос к функциям **«Таролога»** (привязка, карта дня, команды, расклады) требует `status = active AND expires_at > now`. Без подписки бот отвечает: «Эта функция доступна по подписке» + ссылка на оплату внутри Telegram. «Уведомитель» подписки не требует.
- F-18c. Оплата подписки «Таролога» — **внутри Telegram** (Telegram Payments / внешний провайдер; конкретный провайдер выбирается заказчиком после MVP). Сайт в продаже подписки не участвует — продукты раздельные (см. F-11). В v1 закладываются только точки интеграции: создание счёта, webhook оплат, продление/отмена.
- F-18d. Сайт — freemium: базовые функции бесплатны (каталог карт, простые расклады с краткими толкованиями), ИИ-толкования и продвинутые расклады — по подписке. Точная граница free/paid — решением заказчика.

### 3.5. Личный кабинет
- F-19. Регистрация/вход: логин + пароль (как в Help: bcrypt cost 10, cookie-сессия 30 дней, `sameSite=lax`, `secure` в проде).
- F-20. Других способов входа в v1 нет — строго как в Help. (Telegram Login Widget и автовход Mini App по `initData` — кандидаты на v1.1.)
- F-21. Профиль: часовой пояс, время карты дня, вкл/выкл перевёрнутых карт, привязка/отвязка Telegram, смена пароля, удаление аккаунта. Опционально — имя и знак зодиака/дата рождения (паттерн конкурентов: дешёвая персонализация «это про меня»; подставляется в промпт DeepSeek).
- F-22. История раскладов и избранное (см. F-09, F-10).

### 3.6. Встраивание в сторонние сайты
- F-23. Каждый расклад доступен как изолированный iframe-embed: `https://<domain>/embed/<deck-id>/<spread-id>` (пример: `/embed/cosmic-mysticism/celtic-cross`).
- F-24. Параметры темизации через URL: `?theme=dark&accent=gold` (CSS-переменные), чтобы виджет подстраивался под сайт-хозяин.
- F-25. Автовысота iframe через `postMessage` (виджет сообщает родителю свою высоту).
- F-26. Авторизация внутри iframe: сессии через cookie с `SameSite=None; Secure` либо токен в URL для встраиваний (решить на проектировании, зафиксировать в документации).

### 3.7. Telegram Mini App
- F-27. То же веб-приложение открывается внутри Telegram по кнопке бота (`t.me/<bot>/<app>?startapp=...`).
- F-28. Авторизация — по `initData` от Telegram, без логина/пароля; сервер проверяет подпись и выдаёт свою сессию.
- F-29. Адаптация под WebView Telegram: viewport, safe-area на iOS.

### 3.8. ИИ-толкования через DeepSeek
- F-32. При вытягивании карт приложение собирает контекст: расклад, позиции и их смыслы, вытянутые карты (название, прямое/перевёрнутое положение, ключевые слова), вопрос пользователя (опционально, вводит сам).
- F-33. Контекст отправляется в DeepSeek с системным промптом «толкователя Таро». Промпт — отдельный версионируемый артефакт в git: `prompts/tarot-reading.v1.txt` (обновление промпта не требует деплоя кода, только коммит).
- F-34. Требования к промпту: русский язык; структура ответа — общий смысл расклада → по каждой позиции (карта + толкование в контексте позиции) → итог/совет; тёплый тон; запрет выдумывать факты о пользователе; обязательный дисклеймер «носит развлекательный характер, не является медицинской/юридической/финансовой консультацией».
- F-35. Параметры генерации фиксируются в конфиге, а не в коде (ориентир: temperature 0.7, max_tokens ~1200).
- F-36. Кэширование: одинаковые `(spread_id, card_id, position_index, reversed)` — ответ кэшируется (таблица `reading_cache`), повторная генерация не тратит деньги. Персональный вопрос пользователя добавляется поверх кэшированного базового толкования.
- F-37. Fallback: при недоступности DeepSeek показывается статическое толкование из `cards.json` с пометкой «краткое толкование».
- F-38. Лимиты и учёт: счётчик ИИ-запросов на пользователя в сутки (защита от абуза); метрики трат; API-ключ — только в env, запросы идут через существующий прокси (как в Help/English), ключ никогда не попадает в код, репозиторий или логи.
- F-39. Лимиты ИИ: для бесплатных пользователей строже (ориентир: 5 раскладов с ИИ в сутки), для подписчиков — шире (ориентир: 50). Точные цифры — решением заказчика.

### 3.9. Разделы оболочки (как в Help)
- F-40. Оболочка делится на независимые разделы-модули (аналог разделов Help: «Помощник», «Советник по картам»…): например, «Расклады Таро», «Карта дня», позже — «Ленорман», «Руны».
- F-41. Каждый раздел — свой набор колод/раскладов и свой пункт меню; добавление раздела не затрагивает существующие.

### 3.10. Администрирование контента (опционально для v1)
- F-30. Толкования карт и описания раскладов хранятся в JSON в git-репозитории (не в БД) — правки через коммиты.
- F-31. (Желательно) простая админ-страница предпросмотра: выбрать колоду/расклад → увидеть, как выглядит.

### 3.11. Мультиязычность (RU / EN / ES)
- F-42. Выбор языка при регистрации + переключатель в профиле и на сайте (до регистрации). `users.locale` ∈ {ru, en, es}; по умолчанию — из языка браузера.
- F-43. Все строки интерфейса — через i18n-словари (`locales/ru.json`, `en.json`, `es.json`); захардкоженных строк на одном языке в коде нет.
- F-44. Контент (названия и толкования карт, описания раскладов, тексты бота) — на трёх языках (структура — в 4.1).
- F-45. DeepSeek: системный промпт — отдельный версионированный файл на каждый язык (`prompts/tarot-reading.v1.ru.txt`, `.en.txt`, `.es.txt`); ответ всегда на языке пользователя; ключ кэша толкований включает локаль.
- F-46. Бот общается с пользователем на его языке; команда `/language` — смена языка.
- F-47. Embed-параметр `?lang=es` для встраиваний; определение языка — приоритет: параметр URL → профиль → браузер.

### 3.12. Каналы уведомлений (абстракция)
- F-48. Отправка уведомлений идёт через интерфейс `Notifier` с реализациями на канал. v1 — только Telegram.
- F-49. WhatsApp — будущий канал (не v1): технически реализуемо через официальный WhatsApp Business Platform (Cloud API), но существенно тяжелее Telegram — верификация бизнеса в Meta, отдельный номер телефона, проактивные сообщения (карта дня) только по заранее одобренным шаблонам, оплата за каждое доставленное сообщение (с 01.10.2026: первые 1000 сервисных сообщений в месяц на номер бесплатно, далее поштучно, ~$0.001–$0.06 в зависимости от страны). Неофициальные шлюзы — запрещены для продукта (риск бана номера). Архитектура не должна захардкоживать Telegram: WhatsApp добавляется второй реализацией `Notifier` по решению заказчика.

## 4. Модель данных

### 4.1. Карта Таро (`decks/<deck-id>/cards.json`)

```json
{
  "id": "major-00",
  "number": 0,
  "name_ru": "Шут",
  "arcana": "major",
  "image": "00-fool.webp",
  "keywords_ru": ["начало", "спонтанность", "прыжок в неизвестность"],
  "upright_ru": "краткое значение в прямом положении",
  "reversed_ru": "краткое значение в перевёрнутом положении",
  "description_ru": "полный текст толкования (абзац)",
  "love_ru": "трактовка в контексте отношений (опционально)",
  "career_ru": "трактовка в контексте карьеры (опционально)",
  "element": "air", "planet": "uranus"
}
```

Статические поля `upright_ru` / `reversed_ru` / `description_ru` используются двояко: как **fallback** при недоступности DeepSeek и как **контекст** для системного промпта (модель опирается на них, а не выдумывает значения с нуля).

**Мультиязычность (v1.3):** все текстовые поля карты — объект с ключами `ru` / `en` / `es`:
`"name": {"ru": "Шут", "en": "The Fool", "es": "El Loco"}`, аналогично `keywords`, `upright`, `reversed`, `description`, `love`, `career`. (В примере выше для краткости показан плоский вид с суффиксом `_ru`; каноническая форма — вложенный `i18n`-объект.)

Для младших арканов — те же поля, плюс `"suit": "wands" | "cups" | "swords" | "pentacles"` и `"rank": "ace" | "2".."10" | "page" | "knight" | "queen" | "king"`; `"number"` — сквозной номер карты 0–77 (0–21 старшие арканы, 22–77 младшие).

### 4.2. Расклад (`spreads/<spread-id>.json`)

```json
{
  "id": "celtic-cross",
  "name_ru": "Кельтский крест",
  "description_ru": "глубокий разбор сложной ситуации",
  "deck": "cosmic-mysticism",
  "allow_reversed": true,
  "positions": [
    {"index": 0, "x": 0.35, "y": 0.45, "rotation": 0,   "meaning_ru": "Сердце вопроса — настоящее"},
    {"index": 1, "x": 0.35, "y": 0.45, "rotation": 90,  "meaning_ru": "То, что пересекает — вызов"},
    ...
  ]
}
```

Координаты — относительные (0..1) от области «стола», поворот — в градусах. Это покрывает особенности вроде кельтского креста (карта 2 поверх карты 1).

### 4.3. Пользовательские данные (БД)

- `users`: id, username, password_hash, locale (ru/en/es, default ru), timezone, daily_time, daily_enabled, use_reversed, whatsapp_phone (nullable, задел на будущее), notify_channel (telegram | whatsapp, default telegram), created_at.
- `telegram_links`: user_id, bot (notifier | tarolog), telegram_user_id (unique в паре с bot), linked_at — привязки обоих ботов к одному аккаунту.
- `telegram_codes`: code_hash, telegram_user_id, used, expires_at (TTL 10 минут) — как в Help.
- `readings`: id, user_id, spread_id, deck_id, cards JSON (id карты + позиция + перевёрнута), created_at, favorite.
- `daily_log`: (user_id, date) unique — реестр отправок карты дня.
- `subscriptions`: user_id, plan, started_at, expires_at, status, payment_provider, external_id — платные подписки (см. 3.4.1).
- `reading_cache`: (spread_id, card_id, position_index, reversed) unique → cached_text — кэш ИИ-толкований (см. F-36).

### 4.4. Задел на другие системы (не v1, но модель не должна мешать)

Абстракция: «набор элементов + способ случайного выбора + расклад (позиции) + тексты значений». Опции на уровне колоды/системы: `reversed` (вкл/выкл), `draw_mode` (`pick` | `toss` для рун), `significator` (Ленорман), `combinations` (таблица пар Ленорман), `changing_lines` (И-Цзин). Детали — в `research-spreads.md`.

## 5. Интеграция Telegram (детально)

- **Бот:** один на всех пользователей, токен — только в env (`TELEGRAM_BOT_TOKEN`), в коде/репозитории — никогда.
- **Приём апдейтов:** webhook на Workers (как в Help): `POST /telegram-webhook/notifier` и `POST /telegram-webhook/tarolog` — по эндпоинту на бота. `TELEGRAM_WEBHOOK_SECRET` — **обязателен** (в отличие от Help, где он опционален).
- **Привязка:** два направления (основное — сайт→бот через `/link КОД`; запасное — бот→сайт через ввод кода в кабинете). Код одноразовый, TTL 10 минут, хранится хэш. Rate limit на генерацию/ввод кодов.
- **Отправка:** очередь с лимитером (~25 msg/sec глобально); при 429 — ждать ровно `retry_after` и повторять. Бот не пишет первым, пока пользователь не нажал /start.
- **Карта дня:** планировщик тикает 5–15 минут → выборка по локальному времени → `sendPhoto` + подпись + кнопка deep link → запись в `daily_log`.

## 6. Авторизация (по паттерну Help, с улучшениями)

1. Регистрация `POST /api/auth/register` {username, password}: валидация (username ≥ 3, пароль ≥ 8 символов — строже, чем в Help), bcrypt hash cost 10–12, сразу логин.
2. Вход `POST /api/auth/login`: generic 401 без уточнения, что неверно.
3. Сессия: подписанная cookie (`SESSION_SECRET`), 30 дней, `HttpOnly`, `sameSite=lax` (для iframe-embed — `None; Secure`, решить на проектировании), `secure` в проде.
4. `GET /api/auth/status` → `{authed, telegram_connected, ...}`.
5. Rate limit на register/login/connect-telegram: 20 запросов / 15 минут на IP (в отличие от Help — хранить счётчики в БД/Redis, а не in-memory).
6. Telegram Login Widget и Mini App `initData` — как альтернативные входы (раздел 3.5).

## 7. Архитектура и стек (рекомендация)

- **Фронтенд:** vanilla HTML/CSS/JS без сборщика. Один код обслуживает сайт, iframe-embed и Mini App (entry-point определяется URL). Стили — CSS-переменные для темизации.
- **Бэкенд:** Node.js + Express на **Cloudflare Workers** — как в Help: один деплой обслуживает API сайта, бота (Telegraf или grammY) и крон (Workers Cron Triggers).
- **БД:** **Neon Postgres, бесплатный тариф** (как в Help); ORM — Prisma, схема в git.
- **ИИ:** DeepSeek через существующий прокси (как в Help/English); системный промпт толкователя — версионированный файл в git.
- **Контент:** JSON в git (`decks/`, `spreads/`, `prompts/`); изображения — статика/CDN (для бота кэшировать `file_id` после первой отправки).
- **Почему так:** у заказчика уже есть эта инфраструктура (Help) — нулевые новые затраты на старте, знакомый деплой, один репозиторий на всё.
- **Принцип «одно ядро — два лица»:** бэкенд, БД, колода, движок раскладов, ИИ-модуль и планировщик — общие; два Telegram-бота — лишь два интерфейса поверх ядра. Любая фича пишется один раз и доступна обоим направлениям.

## 8. Нефункциональные требования

- **Безопасность:** секреты только в env; `TELEGRAM_WEBHOOK_SECRET` обязателен (если webhook); helmet с полным CSP (нет `/tv`-страницы как в Help, ничто не мешает); строгий CORS-allowlist; отсутствие секретов в логах (коды привязки — только хэши); парольная политика ≥ 8 символов.
- **Надёжность:** планировщик идемпотентен (реестр `daily_log`); падение отправки одному пользователю не роняет весь тик; 403 → деактивация подписки.
- **Производительность:** страница расклада < 2 сек до интерактива на 4G; изображения карт — WebP, ленивая загрузка.
- **Адаптивность:** мобильные экраны в первую очередь (расклады смотрят с телефона); кельтский крест на узком экране — вертикальная прокрутка «стола» допустима.
- **Доступность:** весь интерфейс на русском; тексты толкований — без эзотерического жаргона там, где можно проще.

## 9. Этапы работ

**MVP (оценка: 3–4 недели одного специалиста):**
1. Каркас: Node.js + Express на Cloudflare Workers, Neon Postgres (free) + Prisma, деплой по образцу Help.
2. Авторизация (логин/пароль, сессии) + личный кабинет (таймзона, настройки) — строго как в Help.
3. Движок раскладов + 4 расклада v1 (карта дня, да/нет, 3 карты, кельтский крест) на колоде «Космический мистицизм» (78 карт).
4. Контент: базовые тексты толкований 78 карт для fallback и контекста промпта (пишет заказчик или специалист — см. п.10).
5. DeepSeek: системный промпт толкователя (`prompts/tarot-reading.v1.txt`), кэширование, fallback, лимиты.

## 10. Решения заказчика (зафиксированы) и открытые вопросы

**Решено:**
1. v1 — **78 карт** (22 старших + 56 младших, единый стиль и размер 1280×1920).
2. Бизнес-модель: **оба направления — freemium** (что-то бесплатно, что-то платно): и сайт, и «Таролог». Подписка закладывается в v1 (таблицы, проверки, paywall), подключение платежей — после MVP.
3. Авторизация — **строго как в Help**, без альтернатив в v1.
4. Исполнитель ТЗ заранее неизвестен (человек или ИИ) — документ должен быть понятен любому читателю.
5. Толкования — **через DeepSeek** (системный промпт версионируется в git, кэширование, fallback на статические тексты, лимиты).
6. Инфраструктура — **Cloudflare Workers + Neon Postgres (free)**, стек как в Help (Node/Express, Telegraf/grammY, Prisma).
7. Расклады — независимые плагины: новый расклад = JSON + запись в registry, без правок ядра.
8. Три языка (RU/EN/ES) — с первого дня: переключение при регистрации и в профиле, весь интерфейс/контент/бот на выбранном языке.
9. WhatsApp — технически возможен через официальный Business Platform (верификация, шаблоны, поштучная оплата), но v1 — только Telegram; в архитектуре закладывается абстракция канала уведомлений.
10. Два направления — одно ядро: внешне независимые (допустимо — «конкурирующие») продукты, общий владелец не афишируется. (A) «Таролог» — платный Telegram-бот, конкурент ArcanaGuruBot, оплата внутри Telegram. (B) Сайт + бесплатный бот «Уведомитель» («расклад готов» → возвратный трафик). Внутри: один бэкенд, одна БД, ничего не дублируется.

**Открытые вопросы:**
1. Базовые тексты толкований 78 карт — поручит ИИ (возможно, нескольким параллельно — мне и другому, сравнит качество). Статус: ждёт команды заказчика.
2. Домен — **тот же, что у Help** (решено).
3. Имя бота и название приложения — придумает заказчик.
4. Платёжный провайдер для подписки (ЮKassa / Stripe / Telegram Payments) — выбор после MVP.
5. Лимиты ИИ-раскладов — **5 в сутки бесплатно, 50 для подписчиков** (решено, цифры настраиваемые, поменяем при необходимости).
6. Точная граница free/paid: что именно бесплатно, а что по подписке — отдельно на сайте и в «Тарологе».

## Приложение C. Конкурентный анализ (краткие выводы)

Полный разбор — в `research-competitors.md` (12 проектов: Labyrinthos, Biddy Tarot, Trusted Tarot, Tarot.com, MysticX, Keen, «Аркана | ИИ-таролог», ArcanaGuruBot, «Живое Таро» и др.).

**Что подтверждает решения ТЗ:**
- Карта дня пушем каждое утро — стандарт ниши (все русские боты так делают). Механика из ТЗ рынком подтверждена.
- iFate подтверждает архитектуру «оболочки»: таро + И-Цзин + руны + нумерология под одной крышей — мультисистемность работает у других.
- Стандартный набор раскладов везде одинаков: карта дня → 3 карты → да/нет → кельтский крест → любовные → карьерные.

**Что важно учесть:**
- Масштаб — **153,5 тыс. пользователей в месяц** (проверено лично 2026-10-15 на t.me/ArcanaGuruBot; в более ранних данных было 41,5 тыс.) — доказательство, что ниша в Telegram живая и растёт.
- Модель «сайт бесплатно / бот по подписке» в чистом виде почти не встречается — обычно freemium внутри одного канала. Ценность подписки придётся показывать явно: пуши, безлимит уточняющих вопросов к ИИ, эксклюзивные расклады.
- Встраиваемых виджетов нет ни у кого — все standalone. `/embed` из ТЗ — окно возможностей.

**4 механики монетизации у конкурентов:**
1. Freemium-приложение: бесплатные расклады + кредиты за ИИ-толкования (Labyrinthos: $0.99–$6.99).
2. Маркетплейс живых мастеров поминутно (Keen: $1.99–$30/мин).
3. Воронка в обучение (Biddy Tarot: курсы $495–$1997).
4. Telegram-бот freemium с внутренней валютой (дейлики за вход).

**Идеи для заимствования (кандидаты на v1.1+):**
- Журнал раскладов + «Зеркало» (статистика своих карт: самая частая карта/масть) — дешёво, сильный retention.
- Диалог-уточнения с ИИ после расклада (как у MysticX).
- Дейлики за вход, ритуал-настройка перед гаданием, персонализация через знак зодиака, несколько колод на выбор.
- Физическая колода как мерч: Labyrinthos продаёт свои колоды (~$55) и воркбуки — наша авторская колода из 78 карт готова к печати, это отдельный доходный канал на будущее.
